# Apple Design

Apple 如何构建那些不再感觉像电脑，而开始感觉像你身体延伸的界面。这些知识来自Apple的 WWDC 设计讲座——主要是《设计流畅界面》（WWDC 2018）——经过提炼并转化为 Web 平台（CSS、指针事件、`requestAnimationFrame`、Motion/Framer Motion 等弹簧库）。

核心主线是：**当动效从屏幕上的当前值开始，继承用户的速度，向前投射动量，并且可以在任何瞬间被抓住并逆转时，界面就会感觉充满活力。** 弹簧是让这一切变得自然的工具，因为它们本质上是可中断且能感知速度的。

## 核心理念

> "当我们让界面与我们思考和移动的方式对齐时，神奇的事情就会发生——它不再感觉像一台电脑，而开始感觉像我们自身无缝的延伸。"

当界面表现得像物理世界时，它就是流畅的：事物即时响应，连续移动，携带动量，在边界处产生阻力，并且可以在运动中途被重新定向。以下所有内容都是为了更接近这一目标。

Apple将设计定义为服务于人类的四种需求：**安全/可预测性、理解、成就和愉悦。** 这里的每一条规则都服务于其中之一。

## 1. 响应——消除延迟

一旦出现延迟，直接操控的感觉就会"断崖式下跌"。响应是构建其他一切的基础。

- **在手指按下时响应，而不是在释放时。** 按钮被按下的瞬间就应高亮。等待 `click`/手指抬起事件才给出反馈会感觉死气沉沉。

- **警惕每一次延迟。** 审查防抖、人为定时器、过渡等待以及约 300 毫秒的点击延迟。输入路径上任何非必要的延迟都是退步。

- **反馈必须在交互*期间*持续，而不仅仅在结束时。** 对于拖拽、滑块或抽屉，在整个过程中让 UI 与指针 1:1 地更新——绝不要只在手势完成时才进行动画。

```css
/* 反馈存在于按下瞬间，并且是即时的 */

.button:active {
  transform: scale(0.97);

  transition: transform 100ms ease-out;
}
```

## 2. 直接操控——1:1 追踪

> "触摸和内容应该一起移动。"

当用户拖拽某物时，它必须紧贴手指——并且尊重从*他们抓取的位置*开始的偏移。在抓取时立即吸附到元素的中心会立刻打破这种幻觉。

- 使用带有 `setPointerCapture` 的指针事件，以便即使指针离开元素边界，追踪也能继续。

- 追踪一个简短的**速度/位置历史**（最近几次 `pointermove` 事件），而不仅仅是当前点——你需要在释放时用到速度。

```js
el.addEventListener("pointerdown", (e) => {
  el.setPointerCapture(e.pointerId);

  const grabOffset = e.clientY - el.getBoundingClientRect().top; // 尊重他们抓取的位置

  // ...追踪位置和时间戳历史以计算速度
});
```

## 3. 可中断性——最重要的原则

> "想法和手势是并行发生的。"

每个动画都必须在任何时刻可中断和可重定向。用户必须能够在飞行中抓住一个正在移动的元素并逆转它，而无需等待动画完成。一个正在关闭的模态框，如果用户再次抓住它，应该跟随手指——而不是先完成关闭，然后再重新打开。

- **绝不要在过渡期间锁定输入。**

- **始终从*呈现*（当前）值开始动画，而不是目标值。** 中断时，读取元素在屏幕上的实时变换，并从那里开始新的动画。从逻辑/目标值开始会导致可见的跳跃。

- **避免为任何手势驱动的交互使用 CSS 过渡和 `@keyframes`**——它们无法在飞行中被平滑地抓住和逆转。弹簧默认从当前值开始动画，这正是中断所需要的。

- **当手势逆转时，混合速度——不要硬切。** 在逆转点用一个动画替换另一个动画会产生速度不连续，形成"砖墙"。能够通过重新定位目标来传递速度的弹簧库可以避免这个问题。（这就是 iOS 的*叠加动画*原生所做的；在 Web 上，选择一个能从当前速度重新定位目标的弹簧库。）
